1.0Your first question — what happens when many tasks compete

The arbiter never sprays. Three separate mechanisms keep a busy list from becoming a busy lock screen — selection (most kinds name exactly one thing), batching (things at the same moment share one notification), and budget (suggestions compete for 10 daily slots at 90-minute spacing).

MechanismRuleWho uses it
Pick oneRank all candidates, name a single task; the rest simply wait. Ranking is plan-order first, then stakes/deadline.Morning prompt, idle, floater (collapses to the plan's next item), prep
Batch into oneItems close in time merge into a single notification whose sentence stays true for all of them.Events (back-to-back cluster → one heads-up), dueSoon (same-hour deadlines → "3 things due by 11:59 PM: A, B, and C"), placement heads-ups (close slots share one)
Budget + spacingMax 10 suggestion-type nudges per day, none within 90 min of another; facts (events, dueSoon) are exempt and seeded first, so a suggestion too close to a class reminder loses its slot to it.Everything in the "counts" lane

So with 12 open tasks you do not get 12 notifications — you get one morning naming the biggest, maybe one idle check-in, whatever facts genuinely land that day, and silence otherwise. Silence is a designed output.

2.0Your second question — what happens when you skip

You skipped…What the machine doesWhat it never does
A timeline slot (planned 12:00, didn't start)The one persistent kind: a follow-up 30 min after the slot, repeating every 2 h, max 4 tries, stops at midnight. Completing or unscheduling the task ends the series instantly.Carry into tomorrow — at midnight the slot is swept and the task returns to Unscheduled, visible, unpunished.
An intended day ("do it Friday", Friday passed)The intent survives as a fact; the slipped task becomes floater-check-in material and fair game for any day's planner again.Show overdue red or a countdown — an intention was never a deadline.
The morning prompt's task, twiceThe task steps aside after 2 consecutive mornings; the next-ranked task gets named — unless the only alternative is a whole importance tier lower, in which case it repeats (a repeat beats the app contradicting its own ranking).Escalate tone. Copy stays factual forever.
Every nudge for daysAfter 3 quiet days (no open, no tap, no completion): one come-back note in Roman's words: "Come back, you have some tasks to complete!" (or the plan variant on an empty list).Guilt. The word "missed" never appears in a re-engagement message.
Ignoring one task's nudges repeatedlyRecorded honestly in outcome rows — and, today, nothing else: the per-task fatigue gate exists but is deliberately OFF until baseline data exists to tune it.Silently suppress the task (yet). When armed: back off after 3 ignores, skipping kinds where silence isn't evidence.

3.0Your third question — is the goal-lapse nudge set up correctly?

Audited today, link by link: the wiring is complete and correct in code. What no static check can prove is the live firing — it needs a goal 30 days untouched (or a DEBUG-shifted clock), which is exactly why you haven't seen one yet: your goals are too young or too active.

  • Builder ✓ fires 30 days after the goal's last activity (or its creation — so a goal never worked on still lapses), wake + 8 h, one candidate per run, monthly cap per goal via its own delivered-marker map.
  • The bait copy ✓ deliberately near-empty — no goal name, no elapsed time, and an explicit calm opener so an anxious user doesn't brace: see the preview below.
  • Category registration ✓ the one classic failure spot — the category array iOS is handed is not compiler-checked — verified: goalLapse is in the registered set.
  • Tap → context handoff ✓ the goal's ID rides the notification, and a tap writes it to the shared app-group keys with a freshness window — the cold-launch-safe pattern.
  • The real message ✓ on arrival, the Tasks message box opens expanded with the goal-lapse hook — AI-written when online (cached per goal per day), a deterministic elapsed-time message when not. Both paths end in the one-tap "20 minutes on it" offer that creates a small linked task.
  • Not yet observed live the only honest gap: no .goalLapse outcome row exists yet because no goal has lapsed 30 days since the feature shipped (Sep 4). To see it without waiting a month: temporarily drop goalLapseAfterDays in NudgeConfig on a DEBUG build.

4.0Every notification, word for word

Quoted from the code. Quoted parts are dynamic. Six discretionary kinds can get an AI-polished body from the copy cache (same facts, warmer phrasing, validated before use); events and dueSoon never do — their bodies carry exact clock times computed at scheduling.

01

Event heads-up

eventBlockEXEMPT
Heads up
Interview in 1 hour (3:00 PM).
Multiple
Back-to-back events cluster into one: "Bio 101 lecture in 1 hour (9:00 AM). You've also got "Lab" at 11:00 AM, so your morning's booked." — or with 3+: "…You've got 2 more back-to-back after that, so wrap anything else first." The body names the event by its own title (Roman, Sep 17 2026); the category noun (Class / Work shift / Appointment…) is only the fallback for a nameless row.
If ignored
Nothing. It's an FYI; going to class IS success. Deliberately actionless — tap opens the app, that's all.
02

Morning prompt

morningPromptEXEMPT
Good morning
Biggest thing on your list: "Finish the essay", due today at 5:00 PM.
Multiple
Names exactly ONE task — highest stakes among tasks doable that day, deadline as tiebreak. Everything else waits.
Skipped
Same task named max 2 mornings running, then it steps aside (unless the replacement is a full tier less important — then it repeats). A passed deadline reads past-tense: ", was due yesterday.", never a growing hours-ago counter.
Notes
Skips packed days entirely. Tap lands in Home chat. Eligible for AI-polished body.
03

Idle check-in

idleCOUNTS
Checking in
Have you gotten started on anything today?
Yes, I'm goodNot yet👎
Multiple
The question is deliberately task-agnostic; internally it attaches to the top-ranked task for the records, but names nobody — no shame vector.
Skipped
"Yes, I'm good" silences it for the day. "Not yet" opens a one-task starter sheet (survives cold launch). Ignoring it: nothing further today.
Stands down
Never fires if a session started, a task completed, or you said you're good.
04

Prep — start early

prepCOUNTS
Time to get ahead
Your deadline is in 4 days. At one session a day that's maybe 4 real shots at "Finish the essay". Start session 1 now?
StartSnooze 30m👎
Variant
Nearer deadlines get the short form: ""Finish the essay" needs a start. Just 25 min. That's it."
Multiple
One task per prep day; the fire DAY comes from the start-by planner, the walk stops at the deadline (never nudges "get ahead" on something already late).
Skipped
Snooze re-fires in 30 min; otherwise the next prep day tries again. Generated study-days are excluded (their dates are the plan, not deadlines).
Overlap
Since Sep 14 it cannot land inside a DIFFERENT task's planned slot (the planned-slot gate, Roman's ruling) — no more prep pushes arriving mid Python-block.
05

Due soon

dueSoonEXEMPT
Due soon
"Finish the essay" is due at 11:59 PM.
Multiple
Same-hour deadlines batch into ONE: "3 things due by 11:59 PM: "A", "B", and "C"." — the "by" time is the latest in the batch so the sentence is true for all.
Fires
2 h before a REAL deadline, once per task ever (delivered-marker map). Since the deadline/intent split, it cannot fire on an intention.
If ignored
Nothing more — one warning per deadline is the contract.
06

Floater check-in

floaterCOUNTS
Are you working on something?
'Organize desk' is still open. Just 15 min. Start there?
StartSnooze 30m👎
Multiple
Collapses to the plan's next item when a plan exists; else the pool of no-deadline, no-upcoming-intent tasks (a slipped intent rejoins here).
Skipped
Rolls to tomorrow's anchor; the wake+6h slot is known to lose to midday event reminders on spacing — deliberately untuned until its outcome rows exist.
07

Come-back

comeBackCOUNTS
Looking ahead
Come back, you have some tasks to complete!
Fires
After 3 quiet days (no open, no tapped nudge, no completion — widget completions count as engagement). Any engagement pushes it forward; it only ever fires for someone genuinely away.
Multiple
Never names a task (Roman's ruling, Sep 14). Two states only: open work exists, or, on an empty list, "Come back! There's got to be something you need to plan." It always speaks after three quiet days.
Tone rule
Roman's verbatim wording, never AI-swapped. Never "you missed".
08

Goal lapse — the bait

goalLapseCOUNTS
Got a minute?
Nothing's wrong. There's just something worth a look when you have a moment.
Design
The notification is deliberately near-empty — no goal name, no elapsed time, an explicit "nothing's wrong". The REAL message waits in the Tasks message box the tap opens (see the audit in §3.0): the goal, how long it's been, and a one-tap "20 minutes on it" offer.
Multiple
One goal per run (earliest-lapsed); at most monthly per goal.
Skipped
Nothing until next month's window. Ignoring a goal bait is never attributed to any task.
09

Placement heads-up

placementLeadCOUNTS
Coming up
"Python session" is set for 12:00 PM, then "Job applications" at 2:00 PM.
Multiple
Slots within 2 h share one heads-up, second task named, further ones counted.
Fires
5 min before your own planned slot — including slots captured from "study at 9am". Actionless (the batch may span tasks).
10

Placement follow-up

placementMissedCOUNTS
Still open
"Python session" was set for 12:00 PM and is still open. Just 25 min. Start there?
StartSnooze 30m👎
The series
30 min after the slot passes, then every 2 h, max 4 attempts, hard stop at midnight — pre-scheduled so it works even if the app never runs. Completing or unscheduling ends it instantly.
Skipped
At midnight the slot sweeps away; the task returns to Unscheduled with no residue. Tomorrow is a clean slate by design.
