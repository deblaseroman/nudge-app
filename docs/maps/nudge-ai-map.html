1.0Where AI lives — and the line it never crosses

Every model call sits on an edge of the system: language coming in, or copy going out. The core — arbiter, planner, scorers — is deterministic Swift. AI-derived facts reach decisions only as cached fields read synchronously, so notification timing is always reproducible from local data.

2.0The router — paranoid in the right direction

Every Home-chat message passes a deterministic gate before any model is chosen. The bias is the design: a wrong "chat" verdict loses a capture (unforgivable); a wrong "task" verdict costs six cents. So the cheap lane takes only what provably carries no work — and every tie pays the Opus toll.

4.0The empty seat — the Tasks-tab chat box

The message box's chat shell is built but deliberately unwired: portrait, bubbles, a text field, canned "nothing is saved yet" replies. Wiring it means answering one question first: what is talking to Nudge *here* for, that Home chat isn't? The shell opens seeded with real context Home never has — the composed message (an overdue task, a goal lapse, a plan announcement) the user just tapped.

  • Q1 — What can it DO? Talk only (C) · talk + capture (A) · talk + act on the seeded item (narrow B) · full B. Everything else follows from this.
  • Q2 — Can it change data? If yes (A or B), every action must run through the existing write paths (capture's validated writes, the editor's `apply`) — never a new model-driven write path. The AI proposes; existing code disposes.
  • Q3 — Which model? Follows from Q1: C = Haiku as-is; narrow B = likely Haiku with a small tool-ish prompt; A / full B = Opus low, routed.
  • Q4 — One brain or two? If both Home and Tasks can capture, they must share the one prompt and write path or they WILL drift — the codebase's oldest lesson.
