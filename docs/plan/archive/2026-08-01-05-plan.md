## Scope boundary — read this first

**Nothing above the Start Session button changes.** Header, message box,
timeline, Start Session itself: untouched. This cycle replaces only what
sits *below* it.

Also: **delete the small "Completed (N)" control** currently under Start
Session. Its contents move into no tab — completed tasks are already
recorded elsewhere. If removing it orphans a code path that has no other
entry point, say so and stop rather than deleting the feature.

## What to build

Replace the stacked sections below Start Session with a horizontal tab
strip. One list visible at a time. Tabs highlight when selected.

**Tabs, left to right:**

1. **Unscheduled** — undated tasks and dated tasks not placed on today's
   timeline. This is what the current "Unscheduled" section holds; the tab
   keeps the name for now.
2. **Today** — tasks placed on today's timeline, merged with
   `sequenceIndex` ordered-plan tasks so there's one notion of "today."
   **Empty state: a "Plan my day" button**, nothing else.
3. **Events** — with two sub-filters:
   - **This week** — events within 7 days
   - **Important** — `stakes == .high`, any date
   These are **two lenses on the same data, not two buckets.** An exam
   three weeks out appears under Important and not under This week; a
   high-stakes event tomorrow appears under both. Do not add a field, do
   not partition. `stakes` is the existing importance signal and the only
   one — see `DESIGN.md`.
4. **Overdue** — past due, not complete, excluding `stakes == .low` (an
   undated chore can't be overdue; existing rule). **A count badge sits
   next to the label** — this is what stops the tab hiding what matters
   most. Label and badge in `NudgeTheme.overdue` red. **Not amber:** amber
   already means high stakes and stale-low, and one color must not carry
   two meanings.

**Default tab on open:** your call — say which and why. Overdue-when-
non-empty is defensible; so is Today.

**Prep-task grouping still applies** inside whichever tab holds them: show
today's prep task for an exam as a normal row, collapse the remaining days
for that same exam behind one "Show N more" control, grouped per exam.
Reuse the Events section's existing pattern, don't invent a second idiom.

## Why

The Tasks tab had grown to five stacked sections plus a timeline, and prep
tasks made it worse by adding up to fourteen near-identical rows at once.
Endless scrolling is the specific failure mode this app exists to avoid —
the planners that work for this audience show less, not organise more.

Tabs also fix the naming lie indirectly: with Today as its own tab meaning
"on today's timeline," Unscheduled stops implying "has no date."

## Constraints

- **Nothing above Start Session is touched.**
- Presentation only. No changes to placement, the arbiter, `ExamPrepSweep`,
  or what any sweep creates.
- `NudgeTheme` only — no new colors, no inline literals.
- Every task must appear in at least one tab. Report anything that lands
  nowhere; that's the vanishing-task bug's shape and it must not return.
- Drag-to-reorder must survive in Today. If merging `plannedStartDate`
  tasks with `sequenceIndex` tasks breaks the gesture, **say so and ship
  the tabs without the merge** rather than guessing at a fix.
- `ROADMAP.md` §1 untouched.
- Tab state on relaunch: pick a behavior and say which.

## Evidence it worked

- Both schemes build.
- Each tab renders with real data, and every current task appears in at
  least one.
- Overdue's badge shows the right count and the tab renders red.
- Today's empty state shows the Plan my day button.
- Important shows a high-stakes event dated beyond this week; This week
  does not.
- Prep tasks collapse per exam.
- Drag-to-reorder in Today, or a clear statement of what blocked it.
