## 1 — The expanded box gets a framed dialogue look

Retro game dialogue box, roughly: a defined border, the character portrait
beside the text, messages sitting in the frame rather than floating as
chat bubbles.

**No typewriter reveal.** Text appears immediately. A delay before you can
read is the wrong trade for this audience.

Keep it restrained — the frame and the portrait carry the feel. No pixel
fonts, no sprite work, no custom assets. `NudgeTheme` colors only; if the
border needs a weight or radius the theme doesn't have, say what you added
and why.

## 2 — The character slot takes an expression

The slot currently takes one optional image. Change it to take an
**expression state** — an enum with a few cases (neutral, asking,
pleased, or whatever set you'd propose) that maps to an image.

Grey placeholder for all cases for now; the point is that swapping in real
art later touches one mapping rather than every call site.

Say what cases you chose. Few is better than many — every case is art
someone has to draw.

## 3 — The dropdown opens the chat too

Whatever dropdown/expand affordance the box has should open the same
expanded state as tapping the character. One surface, two ways in.

## Constraints

- Timeboxed. Rough is fine; say so rather than polishing.
- Home chat untouched.
- No persistence, no API calls, no real capture wiring.
- Collapsed state still shows what it shows today.

## Evidence it worked

- Both schemes build.
- The expanded box reads as a framed dialogue box with a portrait.
- Text appears immediately, no reveal animation.
- The slot takes an expression enum; the mapping is one place.
- Both the character and the dropdown open the expanded state.

## Out of scope

- Real character art; pixel fonts.
- Wiring real capture or real questions.
- Merging or pushing.
