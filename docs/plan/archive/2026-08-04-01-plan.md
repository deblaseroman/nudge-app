## 1 — A quantity task can't be placed on the timeline

"Apply to three jobs with quality applications and follow-ups" — a
`targetCount == 3` task — could not be scheduled onto the time block.

**Diagnose before fixing.** Two candidates, and they need different
answers:

- The placement path doesn't handle quantity tasks. They're the newest
  shape in the model and may be excluded, or have no duration to place.
- The time window blocks it. Job applications likely classify as
  `businessHours`, and if the free gaps are outside those hours it's
  correctly refusing — which is right behaviour presented as a silent
  failure.

Report which it is before changing anything. If it's the second, the fix
is telling the user why, not loosening the rule.

**A quantity task also raises a question worth answering:** what duration
does one get? Three applications isn't a fixed block. Say what it
currently uses and whether that's sensible.

## 2 — Start Session picks from the wrong list

Tapping Start Session shows everything scheduled in tasks. It should
default to **what's next on the Today list** — the thing the plan says to
do now.

- Open with a single suggested task, chosen relative to Today.
- Beneath it, a **Change** button revealing the rest of the user's open
  tasks, as the picker does today.
- Say what rule you used for "next" — earliest placement still ahead,
  presumably, but state it.
- If Today is empty, fall back to the current behaviour.

The point is fewer decisions at the moment of starting. The picker is
still there, one tap away.
