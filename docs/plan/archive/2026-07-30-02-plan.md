## What to build

**1 — The vanishing-task bug.** A task placed on a past day belongs to no
section: Unscheduled checks `plannedStartDate == nil`, Scheduled checks
`isDateInToday`, and a stale placement matches neither. It's also invisible on
the timeline, and nothing ever resets it — `clearPlan` only touches today's
auto placements and both planners skip it. So an unfinished placed task
silently vanishes at midnight. Fix with a rollover sweep that clears a
`plannedStartDate` before today. Say what you did about `plannedIsAuto` —
whether manual placements should survive is a real question.

**2 — The widget's event fetch is unsorted.** It takes "the first 20
informational events" in arbitrary store order. With more than 20 in the
window — five classes a day over two weeks is seventy — today's events may not
be among them, so the widget can omit what's happening today. Sort by date and
scope the predicate to the rendered window.

**3 — `inferCategory` can never emit "exam".** Exam keywords route to
`schoolKeywords`, so an imported exam scores 0.7 where a chat-captured one
scores 0.9. This is the prerequisite for auto-creating study tasks from exam
events.

**4 — Idle's suppression rule is wrong.** It skips when any calendar event
falls in the three-hour window before firing — every school day, and the
rollover hits tomorrow's class too. It conflates "an event exists" with "the
user has been active"; the builder's other signals already measure activity
properly. Report what you think the event check is for before changing it — if
it's "don't nudge someone in class," the busy-window gate already does that.

**5 — Remove the break-it-down kind entirely.** Its action and result-writer
are already gone. Retire together: the kind, `buildBreakItDownCandidates`,
`tappedBreakDown`, `category.breakDown`, `deadlinePrepNotificationsEnabled`
and its Settings row. Keep the profile field as a deprecated tombstone per
`UserProfile`'s documented rule — don't drop the column.

**6 — The "urgent" priority ghost.** The prompt still offers it, `HomeTabView`
preserves it, and it renders three ways across four surfaces. Drop it from the
prompt's allowed values and normalize existing rows to "high".

**7 — `DayPlanRefiner` and the widget skip the learned duration lookup.** Four
implementations, two truncated — a three-hour lab reads as sixty minutes to
the AI planner and widget chart while the busy gate sees three hours.
Consolidate onto one method on `NudgeTask`, which both targets compile. The
widget can't reach `NudgeConfig` — say how you handled the default before
doing it.

**8 — Countdown text is implemented twice and disagrees.** 48h days-away
boundary in the app, 72h in the widget's `countdown()`, and the widget's own
`remainingLine` uses 48h — so it disagrees with itself. Also duplicated:
`ordinalSuffix`, `timeAgo`, `formatClockTime`, and three copies of the
night-suppression pair.

**9 — `TaskSortComparator` doesn't know `sequenceIndex`.** Plan-first ordering
is hand-bolted at seven sites. Move `sortDeadline`, `isOverdue` and the
comparator onto `NudgeTask` with plan-first built in.

**10 — `WidgetColors` hand-copies `NudgeTheme`** with off-by-one RGB in
`background` and `textPrimary` and different alphas for surface/muted/divider.
Also `goalAccent` hardcoded inline at `TasksTabView.swift:837`. Make the
widget read one source if the target boundary allows; if not, say so and fix
the values.

**11 — The `#Preview` container in `ContentView.swift`** is missing four
models (`CompletedTaskRecord`, `TimeBlock`, `CategoryDurationStats`,
`EventDurationStats`). Previews-only, but it's one of three hand-synced schema
lists and it has already drifted.
