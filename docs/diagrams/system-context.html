Exists but has no effect

None of these sits on a main path, so none is drawn.

  1. NudgeActivityReport's app group entitlement: the target's one source file opens no UserDefaults suite and no container.
  2. The Info.plist fallback for ANTHROPIC_API_KEY: no such key is in Nudge/Info.plist or in the build settings, so only the Secrets.plist read and the environment fallback can supply the key.
  3. The Darwin notification com.nudge.sessionStateChanged is posted by the widget extension's intents; no target adds an observer.
  4. NudgeWidgetLiveActivity (a Live Activity view for FocusSessionAttributes) and NudgeWidgetControl are compiled into the widget extension but are not in NudgeWidgetBundle. Nothing requests an activity of that type.
  5. The app target's StartFocusSessionIntent, PauseFocusSessionIntent and EndFocusSessionIntent are referenced by no view; the widget uses its own types of the same names.
  6. The widget target's own PauseFocusSessionIntent is a no-op too: its body only posts the unobserved com.nudge.sessionStateChanged Darwin notification, and no view references it.
  7. NudgeNotificationService.configure(), called at launch, has an empty body.
  8. nudge://start-session is parsed and handled but never sent. nudge://open is sent by the companion widget and handled with break.
  9. Four models are in all three schema lists with no fetch, query, insert or initializer call found in any target: NotificationEvent, SentNotificationFlag, CheckIn and TimeBlock.

Not dead but worth knowing: the app declares two calendar usage strings (NSCalendarsFullAccessUsageDescription in Info.plist, NSCalendarsUsageDescription in the build settings) and calls only requestFullAccessToEvents. No URL scheme is declared in Info.plist or the build settings; the only senders of nudge:// links are the widget extension's own views. The widget extension compiles SharedModelContainer.swift yet opens the store through its own widgetModelContainer, so the two schema lists must be kept identical by hand.
