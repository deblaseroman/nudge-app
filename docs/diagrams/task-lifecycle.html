The overview is a state machine: each stadium box is a set of field values on the row, each arrow is one transition labeled with the main function that makes it. The close-ups show the writers behind each arrow top to bottom; where several arrows enter one box they carry no label, and the cases are listed in the table under the picture. Every box names a file and a function (or what is stored and its file), clicks through to that file at this commit, and carries its parameters, values and rules in a hover tooltip. Overview task-lifecycle-overview.mmd

The model is NudgeTask in Nudge/Models/NudgeTask.swift. Two facts define a task's place in the day: the anchor (dueDate / specificTime, when it is owed) and the plan (intendedDate as the plan day, plannedStartDate / plannedDurationMinutes / plannedIsAuto as the plan time). Completion is isComplete / completedAt. The plan is written through five helpers on the model, with three direct writes outside them: PlacementRollover.swift:123 clears intendedDate on a completed row, TimelineReflow.swift:106, 109 sets plannedDurationMinutes, and the editor clears it (TasksTabView.swift:3729). One arrow per transition, labeled with the main function; the other functions that make the same move are in the target state's tooltip and in the triggers table.

Targets searched

From Nudge.xcodeproj/project.pbxproj: four native targets. Two touch the task model.

  • Nudge (app): every creator, planner, sweep, edit and deletion above; all the readers except the widget's. Entitlements: app group.
  • NudgeWidgetExtension: compiles 26 of the 27 Nudge/Models files (not DistractionSettings.swift) plus NudgeTheme.swift and SharedModelContainer.swift (membershipExceptions), so it reads the same dayLens rule and writes isComplete, completedAt and a CompletedTaskRecord through CompleteTaskIntent on the shared store. Entitlements: app group.
  • NudgeActivityMonitor: reads only the App Group snapshot that DistractionMonitor.writeSnapshot derives from the day lens; it never opens the store.
  • NudgeActivityReport: no task code.

Exists but has no effect

Nothing here sits on the main path, so none of it is drawn in the pictures above; the complete reference diagram shows these dashed.

  1. NudgeTask.prepLeadDays is a tombstone column: nothing reads or writes it.
  2. NudgeTask.recurrence is written by CaptureWriter.apply from the capture response and read by nothing; no repeat is ever generated.
  3. NudgeTask.init(isComplete:completedAt:) parameters are passed only by the DEBUG classifier harness; every live creator leaves them at their defaults.
  4. CalendarService.backfillImportedScheduleOnce is a one-shot migration keyed on nudge.calendarImport.scheduleBackfilledOnce; after its first launch it returns at the guard.
  5. NudgeNotificationService.pickTopOpenTask reads topOpenTask and is called by nothing.
  6. EvalHarness (DEBUG, -nudge-eval) writes intendedDate and skipCount and runs the rollover, the planner, CaptureWriter and ExamPrepSweep on an in-memory store; the app store is untouched. NudgeOutcomeClassifierHarness (DEBUG) inserts and deletes its own rows.
  7. TasksTabView.deleteAllTasksAndEvents is compiled only in DEBUG.
  8. NudgeApp temp dumps (stakes, deadline-intent audit, visibility audit) and DevNotesView print or export the fields and write nothing.

Not dead but worth knowing: the 6 AM background task purges events and runs the arbiter, but the rollover, the commitment sweep and the morning auto-plan only run on a foreground, so a plan day that slipped overnight is still on yesterday until the app is opened. The chat's completion path writes no CompletedTaskRecord, so Stats never counts it.
