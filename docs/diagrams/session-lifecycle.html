Nudge Session Lifecycle

commit ede6774 (2026-10-04) · main · drawn 2026-10-06 · reference: docs/diagrams/session-lifecycle.mmd · page: docs/diagrams/session-lifecycle.html

A focus session is kept in three places: SessionCoordinator's memory in the app process, the activeSessionState key in the App Group, and one Live Activity in ActivityKit. The first state machine follows the session record through suspension, process death and relaunch. The second follows the Live Activity. The close-ups show the calls behind each move. Every box names a file and a function or type, clicks through to that file at this commit, and carries its values in a hover tooltip.

Ends the session but not the Live Activity

  • CompleteTaskIntent.perform (widget checkbox on the session's task) removes the key and calls nothing in ActivityKit.
  • NudgeTaskProvider.fetchTimelineState removes the key once the stored end has passed.
  • The teardown branch of syncIfActivityDismissed (session in memory, key or activity gone) resets the coordinator and does not call endActivity.
  • In each case an activity that is still up is ended later by the next syncIfActivityDismissed call (its leftoverActivity check at L259), by Dismiss once it is stale, or by the endActivity of a later session, which ends every activity of the type.

Targets searched

From Nudge.xcodeproj/project.pbxproj: four native targets. Two touch the session or the Live Activity.

  • Nudge (app): SessionCoordinator, LiveActivityManager, the two attribute types, every start and end caller, a second set of session intents. Build setting INFOPLIST_KEY_NSSupportsLiveActivities = YES. Entitlements: app group group.com.deblaser.nudge.
  • NudgeWidgetExtension: NudgeWidgetBundle registers NudgeTaskWidget, NudgeCompanionWidget and TaskLiveActivityView. Also EndFocusSessionIntent, CompleteTaskIntent and the timeline provider. Compiles Models/TaskActivityAttributes.swift and Models/FocusSessionAttributes.swift from the app folder. NudgeWidget/Info.plist sets NSSupportsLiveActivities. Entitlements: the same app group.
  • NudgeActivityMonitor and NudgeActivityReport: no ActivityKit import, no read of activeSessionState, no use of SessionCoordinator.

Exists but has no effect

None of these sits on a main path, so none is drawn.

  1. NudgeWidgetLiveActivity is a complete Live Activity view for FocusSessionAttributes (with paused states and a progress bar). It is not in NudgeWidgetBundle, and nothing requests an activity of that type.
  2. The Darwin notification com.nudge.sessionStateChanged is posted by the widget's EndFocusSessionIntent, PauseFocusSessionIntent and CompleteTaskIntent. No target adds an observer for it.
  3. PauseFocusSessionIntent exists in both targets with an empty body and no view references it. isPaused is always written false and pausedTimeRemaining is never written, so the widget's paused branches (L584, L989, L1154) never run.
  4. The pause and stop capsules in the widget footer (L998, L1008) are links to nudge://focus-session. They open the Tasks tab and end nothing.
  5. The app target's EndFocusSessionIntent calls cancelSession, and StartFocusSessionIntent only reloads the widget timeline. No view in either target references them; the Dismiss button compiles against the widget target's own type of the same name.
  6. The idle confirmation sheet (TasksTabView L904) would call attemptStartSession, but it never opens: idleProposedTaskID is set only from .nudgeIdleNotYetTapped (L932), which nothing posts, and from nudge.pendingIdleTaskID (L953), which nothing writes. The idle notification's Not yet action writes tappedNudgeAnswerKey instead.
  7. nudge://start-session is parsed and handled (it would start a session on the top open task), but no code builds a URL with that host.
  8. SessionState.breakTime, .getReady, .finalWarning are rendered by TaskLiveActivityView and never written. nextTaskName is always nil, and totalTasksToday and currentTaskIndex are always 1, so the activity always reads Session 1 of 1.
  9. NudgeWidgetControl and StartTimerIntent are the Xcode template control: not in the bundle, and perform does nothing.

Not dead but worth knowing, all read from the code above: the teardown branch of syncIfActivityDismissed leaves a Live Activity up; a session started with Live Activities disabled has no activity, so the next scene-active tears it down through the activities.isEmpty check; the Start anyway alert is attached inside the active-session branch of the view while the picker that sets it opens only when no session is active; and the timer path plays the alarm twice.
